# ADOLAT — Frontend: спецификация

Владелец: Участник 1. Тексты локализации: Участник 4.
Связанные документы: [ARCHITECTURE.md](../ARCHITECTURE.md), [BACKEND.md](BACKEND.md) (полные форматы ответов).

---

## 1. Стек

- Next.js (App Router), TypeScript, Tailwind CSS
- Phaser 3: только сцена суда
- Zustand: состояние
- `next-intl`: локализация, язык в URL
- `openapi-typescript` + `openapi-fetch`: клиент API генерируется из `/openapi.json` командой `make api-client`. Файлы в `lib/api/` руками не редактируются.
- Playwright: smoke-тесты

Фронт **не содержит игровой логики и текстов сценариев**. Он показывает `GameState`, который присылает сервер, и отправляет `action_id`.

## 2. Визуальный стиль

Идея: **pixel-art суд внутри аккуратного современного интерфейса**. Пиксельной должна быть игровая сцена, а не весь сайт.

| Элемент | Решение |
|---|---|
| Палитра | тёмно-синий `#0F1B2D` (фон, доверие), золото `#C9A227` (правосудие, акценты), тёплый белый `#F5F1E8` (бумага, документы), бирюза `#1FA39A` (успех), терракота `#C8553D` (ошибки) |
| Шрифт интерфейса | Inter или Manrope: поддерживают кириллицу и `oʻ gʻ ʼ` |
| Пиксельный шрифт | только для декоративных заголовков в игре. **Перед выбором проверить, что в нём есть кириллица и символ `ʻ` (U+02BB).** Многие пиксельные шрифты их не содержат |
| Документы | карточки «бумаги» со штампами, чек выглядит как чек, договор — как договор |
| Анимации | короткие (150–300 мс), эффект печати текста в диалогах, лёгкий наезд камеры на говорящего |
| Тёмная тема | основная, игра смотрится лучше на тёмном фоне |

Не делать: шаблон админ-панели, таблицы вместо игры, кнопки без визуального отклика.

## 3. Маршруты и путь пользователя

```
/[locale]                      Landing
/[locale]/cases                Выбор дела
/[locale]/cases/[id]           Описание дела + кнопка «Начать»
/[locale]/cases/[id]/pretest   Тест до игры (можно пропустить)
/[locale]/play/[sessionId]     Симулятор суда
/[locale]/results/[sessionId]  Результаты
/[locale]/results/[sessionId]/posttest   Тест после игры
/[locale]/mentor/[sessionId]   AI Legal Mentor (также открывается панелью из Results)
/[locale]/dashboard            Прогресс
```

`locale` ∈ `ru | uz-Latn | uz-Cyrl`. При первом визите язык берётся из браузера, по умолчанию `uz-Latn`.

```
Landing ─► Cases ─► Описание дела ─► Pretest ─► Play ─► Results ─┬─► Posttest ─► Dashboard
                                      (skip) ──┘                  └─► Mentor
```

При первом входе (на Landing или при старте дела) фронт вызывает `POST /api/users`, если в localStorage ещё нет `user_id`.

## 4. Экраны: как выглядят и какие эндпоинты вызывают

### 4.1 Landing `/[locale]`

Состав сверху вниз:
1. Шапка: логотип ADOLAT, переключатель языка (RU / Oʻz / Ўз), ссылка на «Мой прогресс».
2. Hero: слоган «Real Law. Interactive Learning. Responsible AI.» (переведён), короткое описание, кнопка **«Начать обучение»**. Справа — живое превью сцены суда (тот же Phaser-компонент в демо-режиме: персонажи «дышат», судья иногда стучит молотком) или GIF.
3. Три карточки «Как это работает»: изучите дело → участвуйте в процессе → разберите ошибки с AI-наставником.
4. Блок «Правовая база»: какие акты загружены, ссылки на lex.uz, дата последней проверки. Данные из `/api/health` и справочника.
5. Подвал: «Образовательный симулятор. Не является юридической консультацией».

Эндпоинты:
- `GET /api/health` — число статей для блока «Правовая база» (если база недоступна, блок скрывается)
- `POST /api/users` — при нажатии «Начать», если нет `user_id`

### 4.2 Выбор дела `/[locale]/cases`

Сетка карточек. В карточке: иллюстрация, название, категория права, сложность (1–3 звезды), примерное время, изучаемые темы (чипы), метка «Учебная ситуация». Недоступные сценарии — серые карточки с подписью «Скоро» (без кликабельной кнопки).

Эндпоинты:
- `GET /api/scenarios?locale=`

### 4.3 Описание дела `/[locale]/cases/[id]`

- История конфликта: короткий текст и иллюстрация.
- Участники: аватар, имя, роль. **Роль игрока подсвечена** («Вы — представитель истца»).
- Требования сторон.
- Список документов, которые будут доступны (только названия).
- Применимые акты: названия со ссылками на lex.uz и дата, на которую рассматривается дело (`legal_date`).
- Кнопки: **«Пройти тест перед игрой»** и **«Начать без теста»**.

Эндпоинты:
- `GET /api/scenarios/{id}?locale=`
- `POST /api/sessions` — по любой из кнопок. Сессия создаётся сразу; при выборе теста `session_id` передаётся дальше.

### 4.4 Тест до и после игры

Один вопрос на экран, 3–4 варианта ответа, полоса прогресса «3 / 10». После отправки — сводка: результат, для post-теста ещё и сравнение «было 4 → стало 8» с подписью *«Предварительный показатель»*. Для каждой ошибки — объяснение и ссылка на статью (открывает `LegalPanel`).

Эндпоинты:
- `GET /api/quiz/{scenario_id}?kind=pre|post&locale=`
- `POST /api/quiz/{scenario_id}/attempts`
- `GET /api/legal/citations/{id}` — при клике на ссылку

### 4.5 Симулятор суда `/[locale]/play/[sessionId]` — главный экран

```
┌────────────────────────────────────────────────────────────────┐
│ ◀ Выход   Этап 6/9: Исследование доказательств  ▓▓▓▓▓░░░  ⭐ 40 │  ← StageBar
├────────────────────────────────────────────────────────────────┤
│                                                                │
│               [Phaser: зал суда, судья в центре,               │
│                истец слева, ответчик справа, свидетель]        │
│                                                                │
│  [📁 Доказательства]                          [⚖ Справка]      │
│ ┌─ 🧑‍⚖️ Судья ─────────────────────────────────────────────────┐ │
│ │ Представитель истца, какие доказательства вы представляете?│ │  ← DialogueBox
│ │                                                  ▸ далее   │ │
│ └────────────────────────────────────────────────────────────┘ │
│  [Представить чек] [Ходатайство об экспертизе] [Задать вопрос] │  ← ActionMenu
└────────────────────────────────────────────────────────────────┘
```

Слои:
- **Phaser canvas** — зал, персонажи, анимации, кликабельные объекты.
- **React overlay** поверх canvas — StageBar, DialogueBox, ActionMenu, EvidenceDrawer, LegalPanel.

Особые раскладки по этапам:

| Этап | Что показывается |
|---|---|
| `INTRO` | полноэкранная карточка дела поверх затемнённого зала, кнопка «Войти в зал» |
| `CASE_REVIEW` | участники по очереди «выходят» и представляются (реплики `say`) |
| `PREPARATION` | EvidenceDrawer открыт по умолчанию, подсказка «Изучите документы перед заседанием»; кнопка «К заседанию» станет доступной, когда сервер её пришлёт |
| `HEARING_*`, `EVIDENCE_EXAMINATION`, `MOTIONS`, `DEBATE` | основной режим: диалог + действия |
| `DECISION` | модальное окно выбора: варианты требований карточками, у каждой — кнопка «Какая норма?» (открывает справку). Кнопка «Подтвердить» |
| `RESULTS` | анимация оглашения: судья встаёт, звук молотка, затем переход на `/results/[sessionId]` |

Как проигрываются события:
1. Ответ сервера содержит `events[]`. Они попадают в `eventQueue`.
2. Пока очередь не пуста, `ActionMenu` заблокирован.
3. `say` → DialogueBox печатает текст. Phaser: говорящий проигрывает `talk`, камера наезжает. Клик или пробел — сначала дописать текст, потом перейти к следующему событию.
4. `react` → Phaser проигрывает анимацию реакции (кивок, возражение, удивление), без остановки очереди.
5. `stage_changed` → плашка «Этап: Судебные прения» на 1,5 секунды, обновление StageBar.
6. `evidence_added` → значок «новое» на кнопке «Доказательства».
7. `score` → всплывающее «+10» у звезды.
8. `legal_note` → небольшая карточка «⚖ Почему это важно» с кнопкой «Открыть статью».
9. Очередь пуста → показывается `ActionMenu` по `available_actions`.

Кнопки действий по `kind`:

| kind | Вид |
|---|---|
| `question` | «Спросить…» → список вопросов к выбранному персонажу (или клик по персонажу в сцене) |
| `evidence` | кнопка с иконкой документа; также можно «перетащить» из EvidenceDrawer |
| `motion` | кнопка с иконкой свитка «Заявить ходатайство» |
| `objection` | акцентная кнопка «Возражаю!» |
| `argument` | список аргументов карточками |
| `decision` | модальное окно (см. `DECISION`) |
| `continue` | «Далее» |

Рядом с действием, у которого есть `hint_citation_ids`, — маленький значок ⚖. Он открывает справку без выбора действия.

**EvidenceDrawer** (выезжает слева): список документов (договор, чек, переписка, объяснения, заключение эксперта). Документ открывается как «бумага» на весь экран. Если сервер присылает действие `review_<evidence_id>`, открытие документа отправляет это действие (оно ставит флаг на сервере).

**LegalPanel** (выезжает справа, общий компонент на всех экранах):
- название документа и его тип;
- номер и название статьи;
- статус редакции: зелёный «Действующая редакция» / серый «Историческая редакция на {дату}» / оранжевый «Редакция не подтверждена»;
- дословный текст статьи, части разделены;
- `translation_note`, если показан не официальный язык;
- кнопка **«Открыть на lex.uz»** (`source_url`, новая вкладка);
- кнопка «Спросить наставника об этой статье» (после завершения игры).

Эндпоинты экрана:
- `GET /api/sessions/{sid}?locale=` — при загрузке и обновлении страницы
- `POST /api/sessions/{sid}/actions` — каждое действие
- `PATCH /api/sessions/{sid}` — при смене языка во время игры, затем повторный `GET`
- `GET /api/legal/citations/{id}?date={legal_date}&locale=` — открытие справки (кэшировать в памяти)
- `POST /api/sessions/{sid}/npc/{character_id}/ask` — P2, свободный вопрос персонажу
- `POST /api/events` — P1, открытие справки или документа (пачкой раз в 10 секунд)

Ошибки:
- `409 ILLEGAL_ACTION` → тост «Действие недоступно», затем `GET` для синхронизации состояния
- сеть или 5xx → блок «Нет связи с сервером» с кнопкой «Повторить». Не терять текущий диалог.

### 4.6 Результаты `/[locale]/results/[sessionId]`

1. Шапка с итогом: «Иск удовлетворён частично», анимация оценки 70 / 100, доля правильных решений, время.
2. **Плашка-дисклеймер** (всегда видна): «Это учебный результат, а не прогноз реального решения суда».
3. «Ваши решения»: временная шкала по этапам. Каждая точка решения: ✅ / ❌, ваш выбор, правильный выбор, объяснение, чипы статей.
4. «Ошибки» по категориям (доказательства / процедура / материальное право / выбор требования).
5. «Применимые нормы»: список карточек статей, клик открывает LegalPanel.
6. «Что изучить дальше»: рекомендации.
7. Кнопки: **«Спросить AI-наставника»**, **«Пройти тест после игры»**, «Сыграть ещё раз», «Мой прогресс».

Эндпоинты:
- `GET /api/sessions/{sid}/result?locale=`
- `GET /api/legal/citations/{id}` — при клике на статью

### 4.7 AI Legal Mentor `/[locale]/mentor/[sessionId]`

- Слева (на мобильном — сверху свёрнуто) краткая сводка дела: итог и ошибки.
- Чат. Над полем ввода — быстрые вопросы: «Почему я проиграл?», «Какое доказательство я не учёл?», «Какая статья это регулирует?», «Что нужно было сделать иначе?».
- Ответ появляется блоками. **После каждого блока — чипы источников** `[1] ЗоЗПП, ст. X`. Клик открывает LegalPanel.
- Блок с `verified: false` выделен приглушённо с пометкой «Не подтверждено источником».
- `insufficient_sources` → карточка «В загруженной правовой базе недостаточно источников, чтобы ответить уверенно».
- `ai_unavailable` → «AI-объяснение сейчас недоступно. Вот нормы, которые относятся к вашему вопросу:» и список источников.
- Под каждым ответом: «Образовательное объяснение, не юридическая консультация».
- История чата хранится в store. Последние 6 сообщений отправляются в `history`.

Эндпоинты:
- `POST /api/mentor/ask` — SSE. Читать через `fetch` + `ReadableStream`, потому что `EventSource` не умеет POST. События: `sources`, `block`, `done`, `error`.
- `GET /api/sessions/{sid}/result` — сводка дела

### 4.8 Dashboard `/[locale]/dashboard`

- Карточка «Уровень правовой грамотности» (0–100, круговой индикатор, подпись).
- «Прирост знаний»: столбики pre/post по каждому сценарию, подпись «Предварительный показатель».
- «Пройденные дела»: список с итогом и баллом, клик открывает результаты.
- «Частые ошибки»: категории.
- «Рекомендовано»: карточки сценариев.
- Пустое состояние: «Вы ещё не прошли ни одного дела» + кнопка «Выбрать дело».

Эндпоинты:
- `GET /api/users/{uid}/dashboard?locale=`

## 5. Phaser: сцена суда

- Базовое разрешение **640×360**, `pixelArt: true`, `Scale.FIT`, целочисленное масштабирование, если получается.
- Подключение только на клиенте: `dynamic(() => import("@/game/PhaserGame"), { ssr: false })`. При уходе со страницы игру уничтожать (`game.destroy(true)`).
- Слои: фон (стены, окна, герб-эмблема в общем стиле) → мебель (судейский стол на возвышении, столы сторон, трибуна свидетеля, стол секретаря) → персонажи → интерактивные подсветки.

Персонажи и анимации (спрайт-листы):

| Персонаж | Позиция | Анимации |
|---|---|---|
| Судья | центр, на возвышении | idle, talk, gavel (стук молотком), think |
| Игрок (представитель истца) | слева | idle, talk, present (поднимает документ), object |
| Истец (потребитель) | слева, рядом | idle, talk, nervous |
| Представитель ответчика / продавец | справа | idle, talk, object, surprised |
| Свидетель / эксперт | трибуна | idle, talk |
| Секретарь | сбоку | idle (печатает) |

Кликабельные объекты: стол с доказательствами (открывает EvidenceDrawer), персонажи (вопрос, если есть действие `question` для него), судья (справка по процедуре текущего этапа — P2).

Связь с React через Zustand (`game/bridge.ts`):
```ts
useGameStore.subscribe(s => s.current, ev => scene.play(ev));   // say / react / stage_changed
useGameStore.subscribe(s => s.state?.stage, stage => scene.setStage(stage));
scene.events.on("object-click", id => useUiStore.getState().onSceneClick(id));
```
Phaser не вызывает API и не хранит игровое состояние.

Ассеты: `frontend/public/game/` — спрайт-листы PNG и JSON (Aseprite), звуки (молоток, шаги, «возражаю») с лицензиями. Список лицензий — в README. Не использовать персонажей, графику и музыку из существующих игр.

## 7. Локализация

- `frontend/locales/ru.json`, `uz-Latn.json`, `uz-Cyrl.json` — **только тексты интерфейса**: меню, кнопки, подсказки, ошибки, дисклеймеры. Тексты сценария и закона приходят с сервера.
- Ключи типизированы: если ключа нет, сборка падает.
- Переключатель языка меняет префикс URL. Во время игры дополнительно вызывается `PATCH /api/sessions/{sid}`.
- Юридические термины в интерфейсе берутся из глоссария (`scenarios/glossary.json`), который проверяет Участник 4. Машинный перевод терминов без проверки запрещён.
- Проверить, что `oʻ`, `gʻ`, `ʼ` везде отображаются корректно, в том числе в canvas.

---

## 8. Адаптивность

- ≥ 1024px: canvas сверху, overlay поверх, панели выезжают сбоку.
- < 768px (телефон, горизонтально): canvas на всю ширину, DialogueBox и ActionMenu — нижняя шторка, панели на весь экран.
- Телефон вертикально: canvas сверху (16:9), под ним диалог и действия. Игра не должна требовать поворота экрана.
- Все кнопки не меньше 44×44 px, клавиатурная навигация в ActionMenu (стрелки, Enter, пробел).

## 9. Тесты и критерии готовности

Playwright smoke (ru и uz-Latn, 1280×720 и 390×844):
1. Landing → Cases → начать дело → пройти эталонный путь до Results.
2. Открыть статью в LegalPanel → есть ссылка на lex.uz.
3. Сменить язык во время игры → тексты сменились, этап тот же.
4. Mentor: задать быстрый вопрос → появились блоки с чипами источников (или fallback без AI).
5. В консоли нет ошибок.

Готово, когда:
- [ ] Все экраны раздела 4 работают на реальном API, без моков.
- [ ] Нет кнопок, которые ничего не делают.
- [ ] Полное прохождение работает на ru и uz-Latn, на десктопе и телефоне.
- [ ] Каждая статья закона открывается в LegalPanel со ссылкой на lex.uz и статусом редакции.
- [ ] Дисклеймеры видны на Results и Mentor.
